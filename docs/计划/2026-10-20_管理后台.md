# 管理后台方案（词库 + 历史句子）

> 状态：**待审阅**（2026-10-20）。用户选定"网页管理后台"方案（相对于手敲 SQL、远程连数据库），本文是细化设计，审阅通过后实施。

## 一、目标

在浏览器里管理服务器上的数据，不用登录服务器：
- **词库**：按元素查看、搜索、排序；删除不合适的词；改错字；手动新增词。
- **历史句子**：按时间倒序查看每轮拼出的句子、各空是谁填的、得票情况。
- **概览**：各元素词数、历史句子总数、当前在线房间与人数。

不在本期范围：短句模板与预置词的编辑（它们在代码仓库里，改文件推送即可，走 git 有版本记录）。

## 二、访问控制

| 方案 | 优点 | 缺点 |
|---|---|---|
| **A. 管理口令**（推荐） | 简单；口令只存在服务器上；够用 | 口令泄露要手动换 |
| B. 用户名 + 密码 + 会话 | 更像正式后台 | 要做账号表、登录态，超出"越简单越好" |
| C. 只允许指定 IP 访问 | 不用记口令 | 家里/公司 IP 会变，容易把自己锁在外面 |

采用 A：
- 地址：`http://<服务器IP>:6333/admin`。
- 口令放在服务器的 `/etc/tppe/admin.env`（权限 600，只有 root 能读），由 `tppe.service` 通过 `EnvironmentFile` 注入，**不进代码仓库、不进日志**。
- `install.sh` 发现这个文件不存在时，自动生成一个随机口令写进去，并**只在安装输出里显示这一次**；以后想看或想换，在服务器上执行 `sudo cat /etc/tppe/admin.env` 或直接编辑后重启服务。
- **没配置口令时，管理接口整体关闭**（返回 404），这是安全的默认值。
- 浏览器登录一次后，口令只保存在当前标签页里（关掉标签页就失效），每次请求放在请求头里发给服务器；服务器做常数时间比对。
- 防暴力猜测：同一 IP 1 分钟内连续输错 10 次，就锁定 5 分钟（返回 429）。每次失败都记 WARNING 日志，带 IP。

## 三、关键设计：删除用"隐藏"，改字用"隐藏旧词 + 新增新词"

问题：预置词在每次服务启动时会用 `INSERT OR IGNORE` 补写。如果真的从表里删掉一个预置词，下次重启（包括每次自动更新）它又会被补回来；改字也一样，原词会被补回来。

| 方案 | 说明 | 取舍 |
|---|---|---|
| **软删除**（推荐） | words 表加 `hidden` 标记；"删除"只把词设成隐藏，候选词抽取时跳过隐藏的词 | 预置词不会被补回来（记录还在，`INSERT OR IGNORE` 自然跳过）；能撤销；数据库多一列 |
| 真删除 + 记录"已删预置词" | 另建一张表记下删过的预置词，启动时跳过 | 多一张表；删了恢复不了 |

采用软删除。具体行为：
- **删除** = 隐藏，可在"显示已删除"里**恢复**。
- **改字** = 隐藏原词 + 新增一条新词（贡献者记为"管理员"，会继承原词的使用次数）；改成一个已经存在的词时，直接提示冲突。
- **玩家又填了一个被隐藏的词**：这一轮照常使用（不打断游戏），但这个词**保持隐藏**，不会重新出现在候选里（管理员的决定优先）。
- 新增词时，校验规则和玩家输入一致：1–20 个字符、同一元素内不重复。

数据库升级到 v4：`words` 表加 `hidden`（0/1）和 `hidden_at` 两列，沿用现有的增量迁移，不丢数据。

## 四、接口（都要求带管理口令）

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/admin` | 管理页面（页面本身不含数据，登录后才拉数据） |
| GET | `/api/admin/stats` | 概览数字 |
| GET | `/api/admin/words?element=&q=&hidden=&sort=&page=` | 词库列表（每页 50 条；可按 最新 / 使用次数 / 点选次数 排序） |
| POST | `/api/admin/words` | 新增词 `{element, text}` |
| PATCH | `/api/admin/words/{id}` | 改字 `{text}` |
| POST | `/api/admin/words/{id}/hide` · `/restore` | 删除（隐藏）/ 恢复 |
| GET | `/api/admin/sentences?q=&page=` | 历史句子列表（每页 30 条，可搜索） |

## 五、页面

单独的 `admin.html`，沿用游戏的深色风格：
- 顶部：口令输入（登录后隐藏）、概览数字。
- 「词库」标签页：元素筛选（全部 / 时间 / 地点 / 人物 / 事件）、搜索框、排序、"显示已删除"开关；表格列出 词、元素、贡献者、来源（预置 / 玩家 / 管理员）、使用次数、点选次数、最后使用时间；每行可 改字 / 删除 / 恢复；上方有"新增词"表单。
- 「历史句子」标签页：时间、房间号、轮次、句子、四个空的填写人、得票、是否热梗句。

## 六、日志

新增日志命名空间 `tppe.admin`：
- 每次写操作（新增、改字、删除、恢复）记一条 INFO，带操作者 IP 和改动前后的内容。
- 口令错误、被锁定记 WARNING。
- 口令本身不写进任何日志。

## 七、测试要锁住的规则

- 没配置口令 → 管理接口返回 404；口令错误 → 401；连续输错 → 429。
- 隐藏的词不会出现在候选里；隐藏后重启（重新执行预置词补写）也不会复活；恢复后重新出现在候选里。
- 改字后新词出现在候选里、原词不再出现；改成已存在的词 → 409 冲突。
- 新增词时，超过 20 个字符或重复 → 被拒绝。
- 玩家输入一个被隐藏的词：这一轮能用，但这个词仍保持隐藏。
- 写操作都有日志；任何日志里都不出现口令。
- 数据库从 v3 迁移到 v4 后，原有数据都在。

## 八、部署影响

- 推送到 main 后，服务器会自动拉取代码并重启。**但口令文件需要重新执行一次 `sudo bash deploy/install.sh` 才会生成**（它还会更新服务文件，加上 `EnvironmentFile`）。在执行之前，管理后台保持关闭，游戏本身不受影响。
- README 补充"管理后台"一节：怎么打开、口令在哪看、怎么换口令。

## 九、工作量

约 40–60 万 token（输入为主，大部分命中缓存），agent 执行约 1–1.5 小时（含测试和本地浏览器联调），不含审阅时间。
