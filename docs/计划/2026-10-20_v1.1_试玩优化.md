# TPPE v1.1 方案：试玩版优化（端口 / 深色 / 日志 / 热梗 / 倒计时 / 投票）

> 状态：**已实施**（2026-10-20）。用户要求"理解完直接做，需要选择的方案比对利弊后按推荐执行"，本文记录需求与当时的取舍，便于接手。

## 一、需求

第一批：
1. 默认端口改为 6333（本机检查未被占用）。
2. 页面改深色背景。
3. 做到可以直接拉起试玩。
4. 日志细致，便于查错。
5. 多编一些句子，加入近几年的网络热梗句，揭晓时显示出处（和什么有关）与大致时间。
6. 涉及数据存储的地方直接优化。
7. 合并上传 git；README 写一段简单明确、给服务器 agent 照做的部署说明。

第二批（开发中追加）：
1. 进房间时起昵称，**10 个字符以内**。
2. 词条要能看到是谁出的。
3. 每次选词 / 打字有 **30 秒**倒计时，超时随机选一个词条填上。
4. 整句朗读完后留 **20 秒**投票，点别人填的词条投票，被投玩家每票 **+1 分**。

## 二、关键取舍

| 问题 | 方案比较 | 采用 |
|---|---|---|
| 日志组织 | 单文件 vs 按模块命名空间 + 全量/错误两个文件 | 命名空间 `tppe.app/http/ws/room/wordbank/db/client`，`logs/tppe.log` + `logs/error.log`（WARNING+）。查错先看 error.log，按 `room=` / `conn=` grep 能串起一条完整链路 |
| 前端出错看不到 | 只靠玩家截图 vs 前端主动上报 | 新增 `POST /api/client-log`，JS 异常、WebSocket 异常断开、朗读失败都会写进服务端日志（`tppe.client`）。上线前联调时它就抓到了一个真 bug |
| 模板存储 | 进数据库 vs 留在 JSON | 留在 `templates.json`（内容资产跟代码走版本管理），格式升级为 `{id, text, meme}`，id 显式且永不复用，热梗带 `name/source/date` |
| 数据库升级 | 删库重建 vs 版本迁移 | `PRAGMA user_version` 增量迁移（v1→v2→v3，只加列），老库词库不丢；开 WAL |
| "谁出的词条" | 只在揭晓时显示填写人 vs 连候选词也显示最早贡献者 | 两者都做：揭晓卡片显示"元素 · 填写人"；候选词按钮显示 `by 昵称`（预置词显示"预置词"），为此 words 表加 `author` 列，记**最早**贡献者，后来者不覆盖 |
| 倒计时放哪 | 前端计时 vs 服务端计时 | 服务端计时（后台任务每 0.5s `tick()`），只下发"还剩几秒"，前端据此本地倒数显示。避免各端时钟不一致、避免有人改前端绕过 |
| 一人多空怎么计时 | 整轮共用 30 秒 vs 每个空单独 30 秒 | 每个空单独 30 秒（轮到哪个空，哪个空才开始计时）；掉线改派来的空也重新给满 30 秒 |
| 超时选哪个词 | 整个词库随机 vs 该玩家看到的候选里随机 | 优先从玩家看到的候选里随机（"随机选一个词条"的直觉含义）；候选为空则整个词库随机；词库也空用兜底词（不入库），并标记"⏰超时随机" |
| "朗读完"怎么判断 | 等每个客户端上报读完 vs 服务端按字数估算 | 按字数估算（0.25 秒/字，3–15 秒），各端朗读时长不同、有的端没有语音，等上报会被最慢/失败的一端卡住 |
| 投票规则 | 每人多票 vs 每人 1 票 | 每人每轮 1 票，截止前可改票，不能投自己填的词（也不能投自己超时被随机的词）；所有有资格的人都投完就提前结束；单人局无人可投，读完直接结算 |
| 计分归属 | 按分配人 vs 按实际填写人 | 按实际填写人（`answered_by`）；超时随机的词也算给被分配的人。积分只在房间内存里累计，离开房间即清零 |

## 三、改动清单

- 端口：`config.PORT` 默认 6333；启动前检查 Python ≥3.10 和端口占用，占用则打日志退出。
- 深色主题：CSS 变量整体替换，`color-scheme: dark`。
- 日志：见上表；HTTP 中间件记录耗时与来源 IP（兼容 `X-Forwarded-For`）；WebSocket 每条连接带 `conn=` 编号；房间每个状态变化一条日志。
- 数据库 v3：`words.pick_count / last_used_at / author`，`sentences.round_no / answers / meme / votes / auto_filled`。
- 状态机：`waiting → filling → reveal → voting → result → filling…`，计时参数集中在 `config.py`，`Timing` 可注入（测试用小值）。
- 模板：普通句 80 → 120 条；新增网络热梗句（见 `templates.json` 中 `meme` 非空的条目）。
- 部署：`deploy/tppe.service`（systemd）、`deploy/update.sh`（拉取 → 有变更才装依赖重启 → 探活带重试 → 失败回滚），README 部署章节。
