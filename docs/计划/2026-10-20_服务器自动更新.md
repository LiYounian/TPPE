# 服务器自动拉取更新 + 自愈

> 状态：**已实施**（2026-10-20）。依据内部手册《服务器自动拉取部署与自愈》，按本项目实际情况裁剪。

## 目标

本地 push 到 GitHub 的 main 后，阿里云服务器约 2 分钟内自动拉取、重启到新版本；新版本起不来就自动回滚到上一版，服务不中断太久。

## 和手册的对应与裁剪

| 手册要素 | 本项目做法 |
|---|---|
| 定时器 | systemd `tppe-autoupdate.timer`，开机 1 分钟后开始，之后每 2 分钟一轮（手册建议 5 分钟到 1 小时；本项目只拉代码、开销小，取 2 分钟让"推送即上线"更快） |
| 环境自检 | git 仓库 / `.venv` / curl，缺了记日志、退出码 1 |
| 拉取 | `fetch` 带 90 秒超时（国内服务器连 GitHub 不稳）；能快进就快进，快进失败 → `reset --hard` 跟随远端 |
| 部署 | `requirements.txt` 变了才装依赖（走阿里云镜像）；没变更不重启 |
| 探活 | `/health` 轮询 15 次 × 2 秒（手册踩坑 A：一探就判死会每轮误回滚） |
| 回滚 | 装依赖 / 重启 / 探活任一失败 → 回到更新前的提交 → 重装 → 重启 → 再探活，可选 webhook 告警 |
| 防并发 | `flock`，上一轮没跑完时本轮跳过 |
| 窄授权 | sudoers 只放行 `systemctl restart tppe` |
| 单元文件不入库 | 仓库里只放**模板**（`__USER__` 等占位符），由 `deploy/install.sh` 按实际用户和路径渲染后装到 `/etc/systemd/system/`，可重复执行 |
| 数据同步（A/B 期） | 不需要：本项目数据只在服务器的 SQLite 里产生，不从本地传过去 |

## 选择：一键安装脚本 vs 手抄命令

手抄命令要求部署者自己改路径、用户、写 sudoers，容易错（例如服务器上用户是 `admin`、路径是 `~/TPPE`，和手册默认的 `deploy` / `/srv` 不同）。所以写 `install.sh`：自动取执行 sudo 的用户与仓库路径，幂等，重装安全。代价是脚本依赖 Linux 工具（getent / stat -c / visudo / systemctl），**只能在服务器上执行，本机 macOS 无法实测**，只做了语法检查。

## 踩到的坑

- **C locale 下 `$变量` 紧跟中文会被拆错**：bash 在非 UTF-8 环境（systemd 定时任务默认就是）会把 `"$why（"` 里全角括号的字节当成变量名的一部分，触发 `set -u` 的"变量未定义"，脚本在回滚前直接退出。集成测试在 `LC_ALL=C` 下复现了这个问题。修复：变量后紧跟非 ASCII 字符一律写 `${变量}`；单元里设 `LANG=C.UTF-8`；加静态检查测试锁住。
